# Setup (local / development)

This repo ships the cross-platform Flutter source plus the Supabase backend.
Native platform folders (`android/`, `ios/`, `web/`) are **not committed** — they
are generated by `flutter create` so they always match your Flutter version.
CI does this automatically; locally you run it once.

For **production hosting on cPanel**, see [`DEPLOY_CPANEL.md`](DEPLOY_CPANEL.md).

## 1. Prerequisites

- Flutter SDK (stable channel) + Dart — https://docs.flutter.dev/get-started/install
- (Backend) Supabase CLI — https://supabase.com/docs/guides/cli
- (Android signing) a Java JDK 17 + `keytool`

## 2. Run the app

```bash
cd app
flutter create --org com.protourney --project-name turneyapp \
  --platforms=android,web,ios .        # one-time: generate native folders
flutter pub get

# Demo mode (no backend) — fully explorable with sample data, zero setup:
flutter run -d chrome

# With a backend, pass compile-time config:
flutter run -d chrome \
  --dart-define=SUPABASE_URL=https://YOUR.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=YOUR_ANON_KEY
```

`flutter create` never overwrites existing files, so it only fills in the
missing native scaffolding — `lib/`, `pubspec.yaml`, and `assets/` are untouched.

**Demo mode** runs entirely in-memory (an in-app `DemoStore`): sample
competitions, bracket generation, match reporting + auto-resolve, manual-payment
accounts, transactions, admin console — all work with no Supabase configured.
Sign in with any email; an email starting with `admin@` (e.g.
`admin@protourney.test`) gets the **admin** role.

## 3. Backend (Supabase)

```bash
supabase init           # generates config.toml for your CLI version
supabase start          # local stack (Postgres, Auth, Storage, …)
supabase db reset       # applies supabase/migrations/0001 … 0014 then seed.sql
```

Deploy the Edge Functions (note the JWT flags):

```bash
supabase functions deploy qris-create-invoice     # QRIS invoice + registration
supabase functions deploy qris-callback   --no-verify-jwt   # qris.id payment webhook
supabase functions deploy qris-mock-pay           # confirms "Simulate payment" (mock only)
supabase functions deploy manual-create-payment   # bank / e-wallet manual transfer
supabase functions deploy admin-confirm-payment   # admin confirms/rejects a manual transfer
supabase functions deploy resolve-matches --no-verify-jwt   # 5-min auto-resolve + push fan-out
supabase functions deploy send-email              # dispute / receipt emails

# Secrets used by the functions (see .env.example):
supabase secrets set QRIS_MOCK=true PLATFORM_FEE_RATE=0.10 \
  QRIS_API_KEY=... QRIS_CALLBACK_SECRET=... RESEND_API_KEY=... \
  EMAIL_FROM="ProTourney <no-reply@yourdomain>"
```

Schedule the 5-minute auto-resolve: migration `0004_cron.sql` registers a
per-minute `pg_cron` job for the DB transitions. For dispute **emails** and
**push**, also schedule the `resolve-matches` function (Dashboard → Edge
Functions → Cron).

## 4. Builds in GitHub Actions

Workflows live in `.github/workflows/`:

| Workflow | Trigger | Output |
|----------|---------|--------|
| `ci.yml` | every push / PR | `flutter analyze --no-fatal-infos` + `flutter test` |
| `build-android.yml` | push to branch, tags, manual | APK + AAB artifacts |
| `build-web.yml` | push to branch, tags, manual | web bundle artifact |
| `build-ios.yml` | tags, manual | unsigned `.app` artifact |

With **no secrets**, Android builds are **unsigned** (debug-signed, still
installable) and CI is green. Add the secrets below and the *same* workflow
produces a **signed** release.

### Android signing secrets (optional)

Generate a keystore and add four repository secrets:

```bash
keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 \
  -validity 10000 -alias upload
base64 -w0 upload-keystore.jks      # value for ANDROID_KEYSTORE_BASE64
```

| Secret | Value |
|--------|-------|
| `ANDROID_KEYSTORE_BASE64` | base64 of the `.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | store password |
| `ANDROID_KEY_ALIAS` | key alias (e.g. `upload`) |
| `ANDROID_KEY_PASSWORD` | key password |

Optional app-config secrets (`SUPABASE_URL`, `SUPABASE_ANON_KEY`) are injected
as `--dart-define`s; if unset, builds run in demo mode.

## 5. App icon

The launcher icon + web favicon are generated from `branding/logo-mark.svg`.
After editing the mark, re-rasterize and fan out:

```bash
bash tool/render_icon.sh                  # → app/assets/icons/app_icon.png (headless Chromium)
cd app && dart run flutter_launcher_icons # Android + web icons
```

Commit the regenerated `app/assets/icons/app_icon.png` — CI runs
`flutter_launcher_icons` on the committed PNG, it does not re-rasterize the SVG.
